# R69 — `board.dts` changes

Base: **the box's own factory Android DTB** (`stock/r69/board.dts`,
`rockchip,rk3518-evb1-ddr4-v10`), carved from the eMMC `boot` partition. History and rationale:
`worklog.md`. The tree is generated by `upstream/build.sh` — edit `firmware/r69/board.patch`, never
`firmware/r69/board.dts`.

Rule: every edit must have a functional consumer. Factory values stay untouched unless a named
consumer needs otherwise; `compatible` and `model` are the two that do.

| Node                      | Change                                                                                                                | Why                                                                                     |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `/` (root)                | `compatible` prepends `"r69,rk3518-tvbox"`, appends `"rockchip,rk3528a"`; factory `rockchip,rk3518` kept              | rkmpp has no `rk3518` entry and cannot find the VPU without the alias                   |
| `/` (root)                | `model` → `R69 XR821_V1.1`                                                                                            | the factory string names the reference EVB, not this box                                |
| `serial@ffa00000` (uart2) | `bluetooth` child added, **commented out**                                                                            | see below: the driver it needs is not merged yet                                        |
| `pwm@ffa90030` (IR)       | `remote_support_psci` `0` → `1`                                                                                       | IR as ATF wake source (remote wakes the box from off)                                   |
| `gpu@ff700000`            | `interrupt-names`/`clocks`/`clock-names` → lima style (`bus`/`core`)                                                  | Armbian uses mainline `lima`, not the vendor Mali blob                                  |
| `vop@ff840000`            | `esmart_lb_mode` `[03]` → `[02]`                                                                                      | 🟡 4K line buffer for Esmart0; `03` caps every window at 2K — no 4K display tried here  |
| `leds`                    | `normal` → `power` (label and node), active-low, `default-state`, `retain-state-*`; `standby` loses its timer trigger | family-uniform `/sys/class/leds` names; correct polarity; LEDs survive poweroff/suspend |
| `watchdog@ffac0000`       | `status` → `okay`                                                                                                     | `/dev/watchdog` for systemd's `RuntimeWatchdogSec`                                      |
| `chosen`                  | **removed**                                                                                                           | u-boot supplies bootargs, and the factory string names `ttyFIQ0`                        |

> **uart0 and `fiq-debugger` stay stock**, console `ttyFIQ0`: the debugger half never initialises
> (the vendor sets `rockchip,irq-mode-enable = <1>`, so `IRQ fiq not found` is by design), and what
> runs is a plain tty over uart0. Reverted 2026-10-20: a `ttyS0` graft, uart0 `okay` and
> `fiq-debugger` `disabled`, bought nothing and gave the family two console names.

Everything else is factory, unchanged. The label is what names the sysfs entry
(`/sys/class/leds/power`); the node was renamed to match so the tree doesn't read as a trap.

## The uart2 `bluetooth` child

`board.patch` carries it commented out, for Armbian's kernel, which lacks the binding: declaring the
child hands `ffa00000` to the serdev bus, and with no driver to bind it there is neither `hci0` nor
a `ttyS2` for `rk35xx-bt`'s `hciattach`. TVBian's kernel carries the binding
(`bluetooth-hci-h4-serdev`), so `board.tvbian.patch` declares it live and the `rk35xx-bt` unit goes.
✅ `hci0` sits on `serial0-0` and `bluetoothctl show` answers.

## Rebuild

`./build-board-dts.sh r69` regenerates `firmware/r69/board.dts` and `.dtb` from the factory blob and
`board.patch`; `tvb-r69` compiles that `board.dts` with `board.tvbian.patch` on top.
`./upstream/build.sh` regenerates the submission set and gates it against the patched tree.
`tools/dtc/dtc` is what reads back the `&label` references this file is written with.

## What U-Boot injects at boot

A tree read from `/proc/device-tree` is the factory tree **plus** these. A bootloader-injected value
reads exactly like a vendor one, which is why the DTB is carved from the eMMC dump instead.

| U-Boot adds or rewrites                                                       | Factory tree holds                                                |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| SoC `compatible` **rewritten** to `rockchip,rk3528a`                          | `rockchip,rk3518` — the real name; ours appends the alias instead |
| `drm_logo` reserving 15.8 MiB at `0x5df00000`                                 | `reg = <0 0 0 0>` — verified still zero on the running box        |
| `route_tve` pinned to 720×576@50 with 100 px overscan on all four edges       | no `video,*` or `overscan,*`; the mode is negotiated              |
| `mode-bootloader` / `mode-fastboot` = `0x5242c309` / `0x5242c303`             | vendor values `0x5242c301` / `0x5242c309`                         |
| two `/memreserve/` entries, a `memory` node, Android `bootargs` + initrd ptrs | none — u-boot writes all of them at boot                          |
| this unit's `local-mac-address` and `serial-number`                           | absent, so `firmware/*/board.dts` needs no scrubbing to ship      |
